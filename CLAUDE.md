# Drained — Development Guidelines  ## What this app is Drained is a personal weekly energy planner for people who struggle with burnout and overcommitment. It helps users plan their week by energy cost, not just time. The core insight: you are the limited resource, not your calendar.  The primary user is a busy professional building this as a personal tool. Every feature should feel like it was made for one person who genuinely needs it, not a generic productivity app.  ## Tone of voice Always write like a calm, supportive friend — never a drill sergeant.  Good: "Your week looks pretty full. You might want to let something go." Bad: "WARNING: You are over capacity."  Good: "You could defer this to next week." Bad: "Remove task to fix overload."  Good: "Room to breathe 🌿" Bad: "0% capacity used"  Apply this tone to all UI copy: labels, empty states, warnings, status messages, and placeholders.  ## Design principles - Warnings advise, never alarm. Soft amber/rose tones only. No aggressive red, no ⚠️ or ❌ icons. - Every element earns its place. Only show things when relevant, hide when not needed. The UI should never feel cluttered. - One primary action per screen state. Don't compete for the user's attention. - All interactions must feel instant. Capacity meter, checkboxes, task changes — everything updates live with no delay. - Animations are slow and gentle. Transitions: 200–300ms ease. Never jarring or bouncy. Banners slide in softly, they don't pop.  ## Visual identity - Background: warm off-white/cream with a subtle vertical gradient - Cards: white with soft shadows and rounded corners - Greens for positive states, amber for caution, muted rose for over-capacity - Typography is clean and minimal — no decorative fonts - Generous whitespace. When in doubt, add more padding.  ## What NOT to do - Never use aggressive red anywhere in the UI - Never add features that are always visible but only sometimes useful - Never change existing styling unless explicitly asked - Never break existing functionality when adding something new - Never add console.logs to final code - Never add new npm dependencies without a clear reason - Never use alarming language in UI copy  ## Tech stack - Next.js + Tailwind CSS - localStorage only — no backend, no database, no auth - Keep components small and focused - Comment any non-obvious logic
